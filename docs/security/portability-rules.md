# ACL450–ACL453 security boundary

F12 treats repository instructions and compatibility observations as hostile inert data. It has no
filesystem, process, environment, clock, network, model, callback, dynamic-module, client, or write
capability. E07 same-process issuance and exact profile/surface identity are the only accepted
cross-profile authority.

## Fail-closed controls

- The outer record, options, arrays, observations, and recursively validated B03 data reject
  proxies, accessors, symbol keys, inherited fields, sparse/extended arrays, duplicates, cycles,
  malformed values, and excess resources without invoking caller-controlled code.
- Format and behavior observations must point to real B03 ownership and an exact summary in an
  issued E07 comparison. Conflicting client versions for one profile/surface are rejected.
- F03 runs internally. Caller-provided statement classification is not compatibility authority;
  only closed classifications at confidence `0.95` or higher may support a finding.
- Partial inventories, unclassified shared policy, conditional/unknown support, and indeterminate
  or unrelated E07 differences stay explicit uncertainty.
- Comparisons, observations, statements, text, quadratic pair work, diagnostics, and uncertainties
  have immutable defaults and hard ceilings.
- Messages and related labels are fixed. Raw prose never enters them; structured policy and target
  sets enter fingerprints only through SHA-256 digests.
- B08 suppression accepts only the parser directives retained for the exact evaluator-issued
  result. Clones and forged results fail closed.

The evaluator does not prove semantic equivalence, behavioral compliance, feature quality, or
future client support. It reports mechanically supported portability risk and exposes no fix plan.
An orchestrator that supplies false support observations can cause false findings; provenance and
K01/K02/K03 review remain required before those observations can support release claims.
