# Canonical-policy synchronization API

I13 is exported from `@agent-context/resolver` because it composes the D03–D13 profile/syntax
implementations with I11 and I10. It does not add a filesystem, network, command, model, or plug-in
capability to the resolver.

```ts
import { createCanonicalPolicySynchronizer } from "@agent-context/resolver";

const synchronizer = await createCanonicalPolicySynchronizer(selection);
const preview = await synchronizer.preview({
  canonical: canonicalAgentsSnapshot,
  policyId: "repository-policy",
  targets: [
    { targetId: "claude-code", current: claudeSnapshot, priorBase: claudeBase },
    { targetId: "copilot", current: copilotSnapshot, priorBase: copilotBase },
    { targetId: "cursor-agent", current: cursorSnapshot, priorBase: cursorBase },
    { targetId: "gemini-cli", current: geminiSnapshot, priorBase: geminiBase },
  ],
});
```

The canonical source is one complete in-repository `AGENTS.md` snapshot obtained through C02.
Targets are mandatory, unique, and ordered by `CANONICAL_POLICY_TARGET_IDS`. The closed public
result schema is `@agent-context/resolver/schemas/canonical-policy-preview.v1.schema.json`.

## Output contract

Every target records:

- exact target path and format;
- profile, surface, specification snapshot, evidence references, and uncertainty;
- base/current/generated digests and a deterministic three-way decision;
- a stable I11 review patch and its SHA-256 when generation is safe;
- `application` as `existing-file-atomic`, `preview-only`, or `not-applicable`; and
- `semanticEquivalenceClaimed: false`.

`nextBase` is closed v1 metadata containing the exact generated bytes and digests required for a
later three-way comparison. Store it only as local tool state through a separately reviewed
integration; the synchronizer itself writes nothing.

A missing destination produces `state: "preview-only"`. I11 can review `create-document` but
deliberately cannot apply it. Only a clean replacement of one existing generated regular file
produces `state: "ready"`. `apply(target)` accepts that exact, unused, same-instance preview and
delegates to I11, which delegates to I10's atomic compare-and-swap writer.

This is a separate, one-use synchronization capability. The private `ACL254` diagnostic used to
compose an I11 patch is not an I12 rule-registry eligibility decision, is never returned as a
generic diagnostic bundle, and cannot enable or widen generic CLI `--fix`. Only
`synchronizer.apply()` can consume the exact target object held in that synchronizer's private
authority map.

## Supported representations

| Canonical scope  | Claude Code                                  | Copilot GA surfaces                                                        | Gemini CLI         | Cursor IDE/CLI                                                       |
| ---------------- | -------------------------------------------- | -------------------------------------------------------------------------- | ------------------ | -------------------------------------------------------------------- |
| repository root  | `CLAUDE.md`                                  | `.github/copilot-instructions.md`                                          | `GEMINI.md`        | root `.cursor/rules/*.mdc`, always-on                                |
| nested directory | root `.claude/rules/*.md` with exact `paths` | refused while CLI/VS Code path-glob semantics remain unknown/contradictory | nested `GEMINI.md` | refused because the MDC glob grammar and pattern base remain unknown |

The generator does not create `CLAUDE.local.md`, `.cursorrules`, `AGENTS.override.md`, configured
fallback filenames, or multiple overlapping vendor files. Those forms are local-only, legacy,
override, setting-dependent, or duplication-prone and cannot be inferred losslessly from one
canonical document.

Before emitting bytes, the implementation parses the target with the real syntax adapter and runs
inside/outside scope probes through the real profile resolver. Unknown, conditional, contradictory,
broader, or inactive results are refused. Canonical links, HTML comments, frontmatter-like prefixes,
and target-recognized imports/references are also outside the safe automatic subset.
