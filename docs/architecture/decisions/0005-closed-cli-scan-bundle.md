# ADR 0005: Ship scan as a closed audited ESM bundle

- Status: accepted
- Date: 2026-08-09
- Scope: I02 production scan packaging

## Decision

The published `@agent-context/lint` manifest has one JavaScript runtime dependency:
`@agent-context/core`. The scan implementation is an esbuild 0.28.1 ESM bundle targeting Node.js 24.
The complete executable graph—entrypoint, process adapter, router, scan, and auxiliary command
handlers—is bundled. All private workspace engines and third-party JavaScript are embedded. Node
built-ins and the documented public core package are the only permitted external imports. The public
library entry remains a separate side-effect-free ESM module.

The build emits an external source map and a canonical esbuild metafile. A closed-bundle audit
rejects absolute build paths, undeclared or private external imports, and residual local imports.
The build is run twice and every generated byte is compared before an artifact is written or
accepted. TypeScript emits declarations first; the bundle step always runs last in `build` and
`prepack`, so `tsc` cannot become the final JavaScript producer accidentally.

The signed standards `bundled/` tree is copied byte-for-byte into the CLI package. Its file
inventory and digests are compared with the standards source tree during build and pack checks.
Every third-party package represented by the metafile must have a name, version, license expression,
and license/notice text. Those texts form deterministic `THIRD_PARTY_NOTICES`; the pack gate
regenerates and compares the notice inventory.

The pack gate builds the CLI tarball twice and requires byte-for-byte identity, extracts the
tarball, installs only the exact packed core artifact, and exercises the executable under process,
socket, and filesystem-write denial. No private workspace deployment is present in this test.

## Consequences

- Installing the public CLI does not require or expose private implementation packages.
- esbuild is an exact-pinned root development dependency and its reviewed install script is the sole
  entry in `allowBuilds`; it is not a published runtime dependency.
- Runtime standards data remains inspectable and signature-bound instead of being converted into
  generated JavaScript.
- Any new third-party code, external edge, license text, or standards asset changes a reviewed
  generated artifact and must pass the bundle and pack gates.
